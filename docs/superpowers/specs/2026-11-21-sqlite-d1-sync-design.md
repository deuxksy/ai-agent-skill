# SQLite와 D1 수동 복제

## 목적

Vesper-X 작품 현황을 D1에서 조회하고, 다른 컴퓨터에 복원해 수집을 이어간다. 실행할 때마다 Local → D1 또는 D1 → Local을 선택한다. 선택한 원본으로 대상을 교체한다.

## 검토한 방식

- DB 전체 복제. 같은 스키마와 데이터로 복원할 수 있고 유지할 테이블 목록이 필요 없다. 다운로드 직링크 등 운영 데이터도 포함된다. 첫 버전은 이 방식을 선택했다.
- 지정한 테이블과 컬럼만 복제. 공유 범위를 줄일 수 있지만, 수집 재개에 필요한 데이터가 바뀔 때마다 목록을 갱신해야 한다.

## 범위

`cosplay.db`와 `premium.db`를 각각 별도의 D1 DB와 연결한다. 전체 복제는 사용자 스키마와 데이터를 의미한다. SQLite 파일과 D1 사이에서는 호환되는 SQL 스키마와 행을 전송한다. 대상에만 있는 사용자 데이터는 교체 시 삭제한다. 자동 실행, 변경 병합, TSV 변환은 범위 밖이다.

## 실행 절차

1. 두 DB 쌍의 원본과 대상 식별자 및 테이블별 행 수를 표시한다. 누락된 테이블은 0행과 구분한다. 같은 건수도 동일한 데이터임을 보장하지 않는다는 점을 표시한다.
2. 실행자가 승인하면 대상을 백업한다. 확인 후 원본이나 대상이 바뀌었으면 미리보기를 갱신하고 다시 확인한다.
3. 원본 스냅샷을 기준으로 교체한다. 로컬 복원은 임시 SQLite에 가져와 검증한 뒤 파일을 교체한다. D1 반영은 백업과 복원 절차를 확인한 뒤 진행한다.
4. DB마다 스키마와 행 수를 다시 확인한다. 두 DB가 모두 검증된 경우에만 전체 성공으로 표시한다. 중간에 실패하면 다음 DB 반영을 중단하고 완료·실패 범위와 백업 복구 방법을 출력한다. 두 DB에 걸친 원자적 교체는 보장하지 않는다.

## 도구 배치

공통 Python 도구와 사용 절차는 `ai-agent-skill/plugins/dev`에 두는 것을 제안한다. Vesper-X 설정에는 로컬 경로와 D1 DB 식별자를 둔다. Cloudflare 공식 CLI를 사용하고, 전체 복제에 포함되는 다운로드 직링크는 미리보기에 출력하지 않는다. 테스트는 로컬 SQLite와 모의 D1 응답으로 두 방향, 취소, 빈 원본, 스키마 불일치, 중간 실패를 검증한다.
